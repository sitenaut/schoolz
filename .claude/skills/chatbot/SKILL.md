# Chatbot

**It serves the whole community, every age, and searches before it answers.** The prompt once called it the assistant "for public schools", so a senior asking about knitting groups and computer classes got a polite refusal and generic advice while the site listed a dozen of each. Dates on `find_local_events` are optional on purpose (required, the model asked for them or gave up), and `services/chat_search_words.py` bridges "seniors"/"knitting" to what listings say. Prompt-change evaluation: run real turns over several phrasings and read the answers.

**A Localz search is private and crisis comes first** (`docs/LOCALZ_DESIGN.md`, "Chatbot"). `search_resources` logs only category and county, never the words, and hides a shelter-looking listing's address. The prompt puts 911/988/the hotlines before anything else and never asks about immigration status.

**The chatbot (`POST /chat`) straddles the tiers.** Anonymous callers get the public MCP tools plus `find_local_events`. A signed-in caller also gets personal tools (`services/chatbot_personal.py`) that call the existing authenticated GET routes in-process **with the caller's own bearer token** — no new access code, so the chatbot can never see more than that person could by clicking around. These tools are never registered on the public `/mcp` server, which holds no credentials. Read-only; a bad token degrades to public instead of 401ing.
- **Prompt caching** (`services/chatbot.py`): one breakpoint on the stable system block caches every tool definition, shared across visitors; anything varying (today's date) goes after it. `find_local_events`' live category list is names-only, sorted, re-read hourly, so tool definitions stay byte-identical (that's also why it lives in `chatbot_personal.py`, not the static-docstring MCP server). The minimum is 512 tokens on Haiku 5.5 and Sonnet 5.5, well under the anonymous prefix, but 4,096 on Haiku 4.5, where that prefix barely fits: a provider switch back to it can silently stop caching. `max_tokens` holds thinking as well as the reply on Haiku 5.5 and Sonnet: at 1024, most list answers stopped mid-list. A safety decline comes back as HTTP 200 with no text, which `run_chat_turn` turns into `NO_ANSWER_REPLY`. Check `cache_read_tokens` on `chatbot_usage` log lines in Loki.
- **Four Anthropic keys, one per cost centre** (`docs/ENV_SETUP.md`): scheduler scans (`ANTHROPIC_API_KEY`), anything a person starts in the API process (`ANTHROPIC_API_KEY_INTERACTIVE`, swapped in at the top of `main.py` because several services read the key at import), public chat, signed-in chat. Each has its own spend limit, so a run-now executes on the interactive key, not the scans one.
- **Providers are switchable** in /admin → Chatbot (`app_settings` row `"chatbot"`, `services/chat_settings.py`), **separately for anonymous and signed-in** — signed-in chats carry children's data, so moving public traffic to a cheaper provider must not silently move that too. `services/chat_providers.py`: history stays in Anthropic's message shape (what the widget replays); the Gemini adapter translates per call. Provider-only fields ride on history blocks under `_`-prefixed keys (e.g. a Gemini tool call's extra fields, echoed back in case they carry a thought signature) and are stripped before anything goes to Anthropic. The compare panel runs the real loop; judge over several runs, answers vary.
- **Fix a repeated Haiku mistake in code, not the prompt.** Prompt rules alone didn't stop it asking "which town?" for the only Beck Middle, or calling a "Board of Education Election Day" event a closing, and each extra round escalates to Sonnet. So `services/chat_school_hint.py` matches the school a message names before the model runs (one fit: "look it up, don't ask"; several: their names and towns to ask with), and `services/chat_place_hint.py` the local place (an upcoming event venue or a seasonal attraction's venue): told nothing, the model took "Indian Acres" (a tree farm with a light trail) for a school and asked which one. The school hint's "don't ask" is absolute, so a false match is worse than none: a word of a town's name ("Hill" in Cherry Hill was Trenton's Patton J. Hill Elementary, for every Cherry Hill question) or of another place's name ("Indian Acres", "Red Bank Battlefield", "Johnson's Corner Farm") never names a school. Check a matcher change against prod's whole public `/schools` list, not just the test fixture. `get_school_day` answers "is there school on <date>" in one call by the Today view's rules, and calendar items carry `day_effect`. A spend limit or outage reaches visitors as "the assistant isn't available" (`ProviderUnavailable`), not a 500.
- **History is the widget's to replay and the server's to trim.** The widget sends back everything `/chat` returned; `chatbot.trim_history` keeps the most recent whole turns (`MAX_HISTORY_MESSAGES`), cutting only where a user's own message starts so no `tool_use` loses its `tool_result`, and drops an unfinished turn. Every `tool_use` left in history must have its `tool_result` next, or the provider refuses every later turn of that conversation (the round cap used to leave one). The request's `max_length` is only a size guard: at 40 it refused long chats outright.
